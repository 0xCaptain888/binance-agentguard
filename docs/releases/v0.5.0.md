# AgentGuard v0.5.0

## Independently verified ERC-8004 identity registration

This release adds a wallet-only ERC-8004 registration flow to the BSC
testnet deployment console. The service prepares an unsigned transaction and
verifies the owner-signed result through two independent RPC providers.

### Added

- BSC Testnet IdentityRegistry integration using the official registry and
  `register(string agentURI)` call;
- strict public HTTPS origin validation for the registration URI;
- unsigned registration transaction preparation with chain, owner, calldata
  and registry binding;
- event, owner, URI, canonical block and dual-RPC verification of the signed
  registration transaction;
- deployment-console registration panel with owner review, wallet cancel and
  uncertain-status handling, hash recovery, proof inspection and JSON export;
- persisted registration proofs under `.runtime/` after independent
  verification;
- local registry fixture and identity verification coverage;
- registration recovery markers saved before wallet requests, including reload
  after an uncertain response and safe refusal when browser storage is unavailable;
- local EVM port selection excludes the HTTP console port, and browser checks
  wait for the app's HTTP health endpoint instead of any listening TCP service;
- documentation for the owner-signed flow, public-hosting requirements and
  explicit non-claims around marketplace listings and campaign eligibility.

### Verification

- `npm run typecheck` passes;
- `npm run bsc:check` passes, including the local Anvil demo and all 90 Node
  tests;
- `npm run verify:site` passes;
- `npm run judge:check` passes;
- site verification reports `valid: true` with all required signals present;
- [Linux CI on October 25, 2026 (UTC+8)](https://github.com/0xCaptain888/binance-agentguard/actions/runs/40144056531)
  passes all 90 Node tests on Node 20.18 and Node 22, all 18 browser cases, and
  the public-testnet Docker build. Browser coverage includes owner-reviewed
  ERC-8004 registration, proof inspection and interrupted-wallet/storage recovery.
  Local macOS browser execution remains blocked by the Chromium sandbox and is
  not claimed as passing.

### Boundaries

- unaudited, BSC Testnet only;
- the service never holds a private key and never broadcasts a wallet
  transaction;
- real registration still requires a public HTTPS origin, test BNB, a user
  wallet signature and a transaction hash supplied for verification;
- local fixtures do not establish a public registration, marketplace listing,
  independent hire or hackathon eligibility.
